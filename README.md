# 部屋の代替わり・引き継ぎキット

Museとの部屋（サイドチャット）は、会話が長くなるほど、毎回の読み直しにかかる量が増えていきます。対策は「部屋を小さく保つ」ことではなく、頃合いを見て新しい部屋へ代替わりし、文脈は引き継ぎ文書に凝縮して渡すことです。

もう1つの理由は、引き継ぎそのものの質です。引き継ぎは「文書を置いた時」ではなく「相手が始めた時」に終わります。このキットは、その形を定型にした道具一式です。

## 中身

- `SKILL.md` — 代替わりと引き継ぎの進め方（Museへ渡して使います）
- `引き継ぎ文書の型.md` — 引き継ぎ文書に入れる項目の書式
- `新室の憲章の型.md` — 新しい部屋の最初の指示（憲章）の書式

## 最初の一歩

本命は、GitHubから直接取り込む形です。自分のClaudeに次の文を貼るだけで、Claudeがこの保管庫を開いてキットを取り込み、引き継ぎ文書と、新しい部屋への最初の指示文を作ります。新しい部屋を作るのは、ご本人です（Claudeには作らせません）。

> https://github.com/rascalrascal/muse-token-kits を開いて、中身を読んでください。この部屋の引き継ぎ文書と、新しい部屋への最初の指示文を、キットの中の型を使って作ってください。新しい部屋は作らないでください。部屋を作るのは私がやります。文書ができたら、全文を私に見せてください

紹介記事にも、同じ趣旨の「貼るだけのプロンプト」が載っています。

ページを開けない環境では、予備として「ファイルを貼る方法」が使えます。ファイル一式を使うと、進め方そのものを手元に置いて、毎回同じ形で回せるようになります。手順は次のとおりです。

## 使い方（ファイルごとの手順）

### 1. `SKILL.md`（進め方の本体）

1. ファイルを開き、全文をコピーします
2. 新しい部屋は、ご本人が作ります（Claudeに作らせるものではありません）
3. その新しい部屋の最初のメッセージに、コピーした全文を貼って送ります

これで、その部屋のClaudeが進め方を読み、引き継ぎ文書づくりから段取りを始めます。貼るのは新しい部屋の最初のメッセージです（今までの部屋に貼っても動きますが、新しい部屋に土台として置くのが基本の形です）。

### 2. `引き継ぎ文書の型.md`（書式）

進め方の中で「引き継ぎ文書を作る」段階で使います。

1. ファイルを開き、全文をコピーします
2. 引き継ぎ文書を作っている部屋の会話に貼り、「この書式で引き継ぎ文書を作ってください」と一言添えて送ります

Claudeはこの書式に沿って、決め事・現在地・未完の仕事などを項目ごとに埋めた引き継ぎ文書を作ります。

### 3. `新室の憲章の型.md`（書式）

進め方の中で「新しい部屋への最初の指示を書く」段階で使います。

1. ファイルを開き、全文をコピーします
2. 憲章を作っている部屋の会話に貼り、「この書式で新しい部屋の憲章を作ってください」と一言添えて送ります

出来上がった憲章は、新しい部屋の最初の指示として、`SKILL.md` と一緒に（または続けて）新しい部屋へ貼って使います。

## 骨格

1. 発動の目安：1つの部屋の消費の偏りが大きくなった時／読み込み量が目立って上がった時／テーマの区切りがつき、残りが参照用の記録になった時
2. 引き継ぎ文書を作る（決め事・現在地・未完の仕事・呼び方の注意を含む）。旧室の会話全文は写さない
3. 新室を作り、短い憲章＋引き継ぎ文書を読む指示＋最初の仕事だけを送る
4. 新室が引き継ぎを読んで作業を再開したことを確認する。**引き継ぎは、相手が「始めた」と報告するまで完了にしない**
5. 旧室は履歴として残す（しまう形にする）。削除は本人の明示の言葉がある時だけ
6. 旧室に付いていた定期実行の届け先は、新室へ付け替える
